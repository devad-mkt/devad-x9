# Existing-System Ownership Miss

## Planning Lesson

A feature request is not evidence that the feature is absent. Before approving
an implementation plan, bind the current UI/settings path, server authority,
persistence/runtime consumer, accepted integration history, tests, and exact
remaining gap.

The plan must choose `REUSE`, `EXTEND`, `NEW`, or `REPLACE_AUTHORIZED`.
Reject `NEW` without source-backed absence and reject replacement without owner
authority. Sheets, handoffs, memory, and graphs can locate evidence but cannot
replace current source/runtime proof.

Keep the result in one row of the authoritative plan. Do not create a separate
architecture inventory. An unknown owner blocks only the dependent plan item.
