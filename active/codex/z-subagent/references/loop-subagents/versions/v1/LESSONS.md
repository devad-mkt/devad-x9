# Loop Subagents v1 lessons

## What worked

- One channel at a time prevented generic settings from being mistaken for provider parity.
- Luna evidence separated source truth, reference-only behavior, worktree-only UI, and provider/runtime UNKNOWN states.
- The independent reviewer found missing lifecycle honesty, validation, and effect wording that source tests alone missed.
- Returning concrete findings to the same implementer was faster than opening another plan or worker.
- Parent browser proof exposed interaction and overflow issues that hash and source-string checks could not prove.

## What failed or cost too much

- Thin per-channel summaries caused premature UI work and missed conditional fields.
- Letting evidence run multiple channels ahead increased context and staleness.
- Generic cards and universal settings sections looked fast but caused rework because channel workflows differ.
- Source-string assertions are useful regression guards, not behavior proof.
- Repeating status, package, or infrastructure work while local UI rows remained executable delayed product delivery.

## Applied rule

Evidence worker finishes one implementation-grade slice; parent verifies it; implementation and review close that slice; only then does evidence advance. Keep official brand icons and shared native components as explicit visual acceptance items. Save user-marked browser defects before correction and verify them again after the build refresh.
