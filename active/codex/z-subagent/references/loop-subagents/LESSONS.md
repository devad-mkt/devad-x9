# Loop Subagents v1.2 lessons

## Evidence-backed regression: empty-state acceptance hid feature loss

- A rendered Inbox route and correct empty state were treated as browser success even though the test database had zero conversations.
- The current slice's source/tests passed, but a richer preserved implementation contained features that were never entered into the acceptance denominator.
- Agent callbacks were internally consistent, yet the parent did not independently compare historical Git objects, current source, populated runtime behavior, and the user's remembered workflow.

## Applied prevention

- For an existing surface, establish a historical feature-retention ledger before edits.
- A feature-rich page needs a deterministic, non-empty, secret-free fixture that reaches list, selection, detail, mutation-disabled, error, and recovery states.
- A blank screen, zero-row screenshot, route 200, hidden props, or source-string assertion is never browser acceptance for a feature-rich page.
- Conditional settings require a mutually exclusive mode-to-fields matrix; inactive fields must be absent and excluded from validation.
- Parent acceptance must independently reproduce the three highest-risk claims and reconcile reviewer findings against stable bytes.

## 2026-08-13 deeper correction: the wrong base was admitted

- The owner wanted the richest accepted Inbox to be the base. Evidence labeled
  that divergent implementation a candidate, and implementation optimized the
  smaller current surface instead. This was a denominator decision, not an icon
  or fixture bug.
- Internal consistency across evidence, implementation, and review created
  circular agreement. None tried to disprove whether the selected historical
  baseline had been retained in the populated default journey.
- Prevention: bind `OWNER_SELECTED_BASELINE`, make its observable rows required,
  require three disconfirming probes, and let only the owner reject a row.
- Model names are admission requests, not authority. Missing Sol/Terra runtime
  admission must be reported; Luna may do logs/mechanical extraction but cannot
  decide a critical evidence denominator merely because it returned a report.
- Newer backend, tenancy, RLS, migration, PostgreSQL or security work is not
  retained merely because it is newer, expensive, or heavily tested in prose.
  Recovery must bind exact commits, executable tests, receipts, failure modes,
  rollback and negative cross-workspace proof before semantic union.

## 2026-08-14 v1.3 correction: focus and filesystem authority were implicit

- A generic continuation callback pulled work away from an unfinished
  owner-selected recovery slice. The canonical active slice now remains locked
  until owner acceptance or explicit owner-approved defer.
- A restoration patch targeted a neighboring preserved reference worktree after
  command context and intended target diverged. Output truncation increased the
  damage risk. The three reference files were restored to exact Git preimages
  before work resumed.
- Every write packet now binds the absolute target root, read-only reference
  roots, resolved write paths, preimage hashes, containment checks, and a
  wrong-root recovery pointer. Helper callbacks never grant plan-transition
  authority.
