# Admission and Receipts

## Admission: all fields are required before dispatch

```text
SLICE_ID / OBJECTIVE / VISIBLE_ACCEPTANCE_PREDICATE
ACTIVE_PROGRAM_PHASE / ACTIVE_SLICE_ID / ACTIVE_SLICE_STATE / ADVANCE_GATE
REPO / WORKTREE / BRANCH / BASE_SHA / HEAD / UPSTREAM
TARGET_ROOT / REFERENCE_ROOTS_READ_ONLY / RESOLVED_WRITE_PATHS
DIRTY_STATE / OWNED_PATH_BASE_HASHES / READ_PATHS / EXCLUSIVE_WRITE_PATHS
PREIMAGE_HASHES / PATCH_METHOD / TARGET_CONTAINMENT_CHECK / WRONG_ROOT_ROLLBACK
LIVE_ROLE_INVENTORY / VERIFIED_AT / TOOL_RESULT
HISTORY_START / SOURCE_THREAD_IDS / SOURCE_MESSAGE_ANCHORS
HISTORICAL_BRANCHES_SEARCHED / WORKTREES_SEARCHED / MERGE_BASE / PATH_RENAMES
CURRENT_OWNER_PATHS / RETENTION_ROWS / IMMUTABLE_SOURCE_REFS
BASELINE_SOURCE_REF / BASELINE_REQUIRED_FEATURES / OWNER_REJECTED_FEATURES
CURRENT_NEW_WORK_TO_PROTECT / THREE_OMISSION_HYPOTHESES
FIXTURE_ID / SEED_COMMAND / ENV_GATE / EXPECTED_COUNTS / FOREIGN_DECOYS
EXPECTED_INTERACTIONS / MODE_FIELD_VALIDATION_MATRIX
FORBIDDEN_EFFECTS / PLANNED_PROOF_BY_TIER / FALLBACK
BUDGET_CAP / STOP_CONDITION / ROLLBACK_OR_CLEANUP
```

Classify every historical behavior: `REQUIRED_ACCEPTED`,
`HISTORICAL_CANDIDATE`, `OWNER_REMOVED`, or `UNKNOWN`. Never restore a divergent
historical feature merely because it is richer. For feature-rich UI, the fixture
must be populated. For conditional forms, inactive fields must be absent and
excluded from validation.

When the owner explicitly names a previously accepted implementation, commit,
or rich historical surface as the base, bind it in `BASELINE_SOURCE_REF` and
list its observable behaviors in `BASELINE_REQUIRED_FEATURES`. Those behaviors
default to `REQUIRED_ACCEPTED`; neither an evidence worker nor an implementer
may downgrade them to `HISTORICAL_CANDIDATE` or substitute a simplified rewrite
unless `OWNER_REJECTED_FEATURES` records the owner's explicit rejection. New
work must overlay the restored baseline only after its populated journey works.

## Receipt: create after each material stage

```text
RECEIPT_ID / STAGE / PARENT_RECEIPT / SUPERSEDES / OBSERVED_AT
BASE_SHA / CURRENT_HEAD / WORKTREE / CHANGED_PATHS
BEFORE_HASHES / FINAL_HASHES / PATCH_HASH
ACTIVE_SLICE_ID / ACTIVE_SLICE_TRANSITION / ADVANCE_GATE_RESULT
RESOLVED_TARGET_ROOT / TARGET_CONTAINMENT_CHECK / REFERENCE_ROOT_POST_HASHES
OUTPUT_TRUNCATION_CHECK / WRONG_ROOT_RECOVERY_POINTER
DIRTY_UNOWNED_PATHS / COLLISION_SCAN
REQUIREMENT_IDS_COVERED / RETENTION_ROW_VERDICTS
FIXTURE_RUN_ID / EXPECTED_AND_ACTUAL_COUNTS
PROOF_COMMANDS / EXIT_CODES / RAW_OUTPUT_LOCATION / SHA_USED_BY_EACH_PROOF
INTERACTIONS_EXERCISED / DISABLED_EFFECTS / UNKNOWN_OR_NOT_RUN
RETAINED / EXTENDED / OWNER_DROPPED / DEFER_GATED / UNRESOLVED_BACKEND
POPULATED_BROWSER / NEGATIVE_TENANCY_SECURITY_PROOF
ROLLBACK_OR_RECOVERY_POINTER / NEXT_ACTION
```

Receipts are evidence pointers, not acceptance. If bytes, fixture, worktree, or
shared/untracked collision state changes, supersede the old receipt; never reuse
its proof as current.

## Reviewer and parent acceptance

Reviewer returns:

```text
REVIEWER_ROLE_ADMISSION / RECEIPTS_AND_HASHES_REVIEWED
ACTIVE_SLICE_AUTHORITY_CHECK / TARGET_ROOT_AND_REFERENCE_INTEGRITY
INDEPENDENT_COMMANDS_AND_EXIT_CODES / RETENTION_AND_MODE_MATRIX_VERDICTS
OMITTED_OWNER_DENOMINATOR_ROWS / COUNTEREXAMPLES_TESTED
ISSUES(severity,file,location,failed_requirement)
OBSERVABLE_CORRECTION_PREDICATE / TIER_VERDICTS / NO_EDITS_ATTESTATION
PASS | REQUEST_CHANGES
```

Parent accepts only with:

```text
ACCEPTED_RECEIPT_ID / EXACT_COMMIT_OR_PATCH_HASH / OWNED_FILE_HASHES
ACTIVE_SLICE_ACCEPTED_OR_OWNER_DEFERRED / NEXT_SLICE_SELECTION_AUTHORITY
FULL_RETENTION_RECONCILIATION / POPULATED_FIXTURE_AND_JOURNEY / VIEWPORTS
BASELINE_SOURCE_REF / BASELINE_REQUIRED_FEATURES_RENDERED / FEATURE_COUNT_DELTA
FINAL_TIER_MATRIX / NO_UNRESOLVED_P1_P2 / DISABLED_EFFECTS
ROOT_VERIFIED_BASELINE_HASHES / ROOT_VERIFIED_HIGHEST_RISK_BACKEND_CLAIM
REMAINING_UNKNOWN / ROLLBACK_POINTER / UNOWNED_DIRTY_STATE / VERIFIED_AT
```
