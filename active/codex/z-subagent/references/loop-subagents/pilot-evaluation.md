# Pilot Evaluation

Use only to compare LoopSub with a direct bounded worker. Start both from the
same base and acceptance contract; otherwise cost or quality comparisons are not
valid.

Record attested role/model/effort when exposed, duration, final cumulative child
telemetry, retries, parent verification boundaries, review cycles, and outcome.
Do not sum token snapshots or treat plan credits as API USD.

Accept a LoopSub version only when it measurably reduces requirement loss, review
cycles, or total cost/time while preserving proof and safety. Keep the trial
local-only: the preferred first slice is a clean-worktree, four-mode WhatsApp
conditional-schema UI correction with one component, one focused test, browser
mode interactions, and no provider, persistence, credential, network, or live
action. Do not use divergent Inbox restoration, PG/RLS, provider canaries, or
deployment as the first pilot.
