## Result

- Evidence and concise outcome: Use at most one active subagent for the current
  budget-sensitive CHAT goal. The manager should delegate only when the task is
  independently bounded and the expected time or proof benefit exceeds the
  dispatch and synthesis cost.
- Best use case learned: Treat `gpt-5.3-codex-spark` as an old,
  experimental candidate for very low-risk deterministic work that a
  Luna-medium-class model could also complete safely: exact extraction,
  mechanical inventory, simple test triage, or a noncritical shadow check.
  Always provide `TOKEN_MODE: LOW`, named files, expected assertions,
  forbidden actions, a stop rule, and a compact output schema.
- Critical boundary: Spark must not be the accepted authority for security,
  tenancy, architecture, production, money, secrets, destructive actions, or
  irreversible work. Use an appropriate Sol profile and direct manager
  verification for those tasks.
- Calibration rule: Compare Spark only on frozen low-risk packets. Record
  first-pass correctness, missed and false findings, retries, wall time, and
  actual token telemetry when exposed. Do not promote, reject, or claim cost
  savings from unavailable telemetry or one result.
- Context rule: Keep one useful agent's context when the next mission remains
  in the same bounded domain; otherwise stop it and dispatch a fresh
  task-local packet with `fork_turns="none"`. Never keep an idle agent merely
  to preserve context.
- Next profile to try, if any: Spark on one immutable low-risk packet, compared
  later with a Luna-medium or Terra-low-cost equivalent. Escalate only when a
  specific quality failure proves the lower rung insufficient.
