# Repeated Existing-System Ownership Failure

Use this only after the failure class recurs or a claimed new capability is
disproved by current evidence.

## Diagnostic

1. Identify the first plan statement that assumed absence or wrong ownership.
2. Rebind accepted predecessor/merge history to the current Git identity.
3. Trace UI/settings to request, server owner, persistence, runtime consumer,
   result, and focused proof.
4. Separate discovery evidence from authority: Sheets, chats, memory, Graphify,
   and RAG propose candidates; current source/runtime closes the relation.
5. Classify the correction as `REUSE`, `EXTEND`, `NEW`, or
   `REPLACE_AUTHORIZED`.

Apply the lesson to the remaining dependency-ready slices. Do not reopen every
accepted byte. Review prior work only for a concrete duplicate, contradiction,
or unsafe owner split. Deeper reasoning must delete unsupported planned work,
not manufacture a repository-wide audit.
