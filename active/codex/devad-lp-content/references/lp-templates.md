## Landing Page Size Router

Default to Medium / Standard when the user does not choose a size. Do not choose Full / Expanded only because the source is long.

```markdown
## Recommended LP Parts

Selected size:
Reason:
Include:
- Hero and product definition:
- Functional component:
- Feature or benefit cards:
- Proof:
- Objection FAQ:
- Contextual bridge:
- Final CTA:

Exclude:
- [Article-style intro, broad market education, unsupported proof, unrelated sections, CRO tests, or extra template blocks.]
```

```markdown
| Size | Use When | Typical Scope |
|---|---|---|
| Short / Compact | Simple offer, lead magnet, signup page, one-feature campaign, low-friction ecommerce page | 400-700 words, 5-7 sections |
| Medium / Standard | Default for SaaS, service, product, demo-booking, campaign, or lead-capture pages | 800-1,300 words, 7-9 sections |
| Full / Expanded | User requests depth or the offer needs enterprise proof, comparison, security, implementation, regulated-claim caution, or complex objection handling | 1,500-2,500 words, 9-12 sections |
```

## CTA Friction Router

Use this before choosing the CTA. The primary CTA should match source evidence, price, buying model, and visitor commitment.

```markdown
| Source Signal | Default CTA Type | Good CTA Examples | Avoid |
|---|---|---|---|
| Low-cost addon, plugin, module, template, or download | Self-serve purchase or download | Get the addon, Download the module, Install the plugin, Order now | Book a demo |
| Free trial or product-led SaaS | Trial/signup | Start the free trial, Create account, Try the workflow | Talk to sales as primary CTA |
| Quote-led service | Scope/quote request | Estimate my cost, Request a quote, Send project details | Generic submit |
| Enterprise, custom, regulated, high-price, or complex implementation | Sales-led CTA | Book a demo, Talk to sales, Schedule consultation | Instant purchase claims |
```

## Visual Intent Cue

Use directly under sections when the output should guide a designer, developer, page builder, or image/GIF choice.

```markdown
Visual Intent: [Insert/show/use] [specific screenshot, chart, GIF, report preview, UI state, calculator, button, form, or dashboard view] that demonstrates [exact visitor action or decision].
```

Examples:

```markdown
Visual Intent: Insert a 3-second looping GIF showing the user clicking Export and seeing a white-label PDF report preview.

Visual Intent: Show the dashboard with Facebook reach, Instagram interactions, TikTok views, YouTube watch time, and LinkedIn clicks in one comparison row.
```

## Scannable Entity Matrix

Use when a source contains many platforms, integrations, metrics, features, use cases, ingredients, or plan attributes. Keep the copy short and make the dense facts easy to scan.

```markdown
| Entity | Attribute | Source-Backed Value | Visitor Decision |
|---|---|---|---|
| [Platform, feature, module, role, plan, or product] | [metric, integration, output, limit, workflow, or claim type] | [exact source value] | [why this helps selection] |
```

## Awareness Flow Selector

Use the flow silently unless the user asks for strategy.

```markdown
| Awareness Level | First Screen Priority | Body Priority |
|---|---|---|
| Most aware | Offer, price, CTA, risk reducer | Proof, terms, FAQ |
| Product aware | Differentiator, mechanism, CTA | Comparison, feature cards, proof |
| Solution aware | Outcome, use case, mechanism | Feature cards, proof, objections |
| Problem aware | Short problem-to-solution bridge | Product definition, mechanism, proof, CTA |
| Cold traffic | Limited context and clear category | AIDA-style scan path without article drift |
```

## Direct-Response Consumer Product Page

Use this template for ecommerce landing pages that sell one physical product through a direct order form, cash-on-delivery flow, limited-time offer, or package selector. It fits supplements, beauty products, wellness products, single-SKU ecommerce offers, and campaign pages where the main action is `Order Now`.

For supplements, health, children's products, and regulated categories, use only verified claims. Do not invent statistics, medical results, dosage instructions, certifications, licenses, testimonials, before/after claims, or safety statements. Mark missing proof with placeholders such as `[clinical source needed]`, `[license proof needed]`, or `[doctor-review required]`.

```markdown
## Direct-Response Product Brief

Product:
Product type:
Audience:
Buyer:
Primary problem:
One big idea:
Primary CTA:
Offer:
Payment/shipping promise:
Risk reducer:
Proof assets:
Ingredients or components:
Usage instructions:
Safety constraints:
Claims requiring verification:
```

```markdown
# [Primary outcome] for [audience] with [product mechanism]

## [Audience] deserves [safe, specific outcome]
[Product] is a [product category] for [audience] that supports [primary outcome] through [specific mechanism or ingredient group].

Primary CTA: Order Now
Proof cue: [license, customer count, review count, expert proof, or certification]
Visual annotation: [Product packshot, child/user result context, ingredient visual, or order-form preview with exact explanation.]

## Why [problem] needs attention now
Use a short statistic grid only when the numbers are sourced.

| Problem Signal | Percentage or Value | Effect on Buyer/Audience | Source |
|---|---:|---|---|
| [Nutrient deficiency or pain point] | [verified value] | [specific impact] | [source] |
| [Second pain point] | [verified value] | [specific impact] | [source] |
| [Third pain point] | [verified value] | [specific impact] | [source] |

## What [product] supports in one daily routine
List 3-5 benefits that repeat the one big idea.

1. [Benefit tied to primary outcome]
2. [Benefit tied to supporting health/comfort/performance outcome]
3. [Benefit tied to energy, focus, convenience, appearance, or confidence]
4. [Benefit tied to buyer peace of mind]

## Ingredient and benefit cards
Each ingredient, component, or feature needs one isolated card.

### [Ingredient or component]
Entity: [Product ingredient/component]
Attribute: [role or function]
Value: [verified amount, form, source, or supported benefit]
Copy: [Product] includes [ingredient/component] to support [specific benefit]. [Add source or placeholder if this is a health claim.]

## What makes [product] different?
Use this section for verified differentiators only.

- [Differentiator 1: formulation, format, license, certification, concentration, delivery method, or guarantee]
- [Differentiator 2]
- [Differentiator 3]

## Product proof
Use proof that supports the same big idea.

- Customer review: [specific quoted result with attribution]
- License/certification: [exact license or authority]
- Expert proof: [doctor, nutritionist, lab, or study source]
- Social proof: [number of buyers, parents, customers, or repeat orders]

## Choose your offer
Use package cards only when the offer choice is part of the same order path.

| Package | Price | Anchor Price | Incentive | CTA |
|---|---:|---:|---|---|
| 1 pack | [price] | [crossed-out price] | [shipping/payment promise] | Order Now |
| 2 packs | [price] | [anchor] | [discount] | Order Now |
| Best value | [price] | [anchor] | [bonus/free unit] | Order Now |

## Order form
Keep fields minimal and tied to fulfillment.

Fields:
- Full name
- Phone number
- Offer/package
- Address or delivery city, if required

Microcopy:
[Product] ships with [shipping promise]. Payment is available through [payment methods]. [Add return, warranty, or support details if provided.]

## Countdown or urgency
Use urgency only when real.

Offer ends: [date/time or campaign rule]
Reason: [stock limit, campaign window, shipping cutoff, seasonal promotion]

## Safety and usage FAQ
Use direct answers and avoid medical overpromising.

Q: Who is [product] suitable for?
A: [Product] is suitable for [audience/age group] when used according to [label, physician, or professional guidance].

Q: How should [product] be used?
A: Use [product] according to [label dosage or placeholder]. Consult a qualified professional before use for children, pregnancy, medical conditions, allergies, or medication interactions.

Q: Does [product] contain [sugar, preservatives, allergens, ingredient]?
A: [Verified answer or proof placeholder.]

Q: When can buyers expect results?
A: Results vary by person. Use only verified timelines and avoid guaranteed medical, growth, weight-loss, or cure claims.

Q: Is [product] licensed or certified?
A: [Product] is [license/certification status] according to [authority/source]. Use `[license proof needed]` if the source is not provided.

## Final CTA
[Repeat the same order offer, shipping/payment promise, and primary CTA.]
```

## Page vs Segment Checklist

```markdown
Create a standalone page only if:
- The feature, audience, or offer has independent search demand.
- The page can support a unique acquisition goal.
- The page has enough proof and specific attributes to avoid thin content.
- The page will not cannibalize a stronger parent page.

Keep as a segment if:
- The feature is a minor setting, small integration, or narrow attribute.
- The content would repeat a parent page.
- The feature lacks enough proof, differentiation, or commercial demand.
```
