## 1. Universal Failures

Weak reports passed file-count validation while they:

- summarized requests instead of tracing requirement rows;
- treated hooks/menu entries as installed features;
- used visible examples instead of a full denominator;
- skipped hidden, error, mobile, keyboard and recovery states;
- skipped administrator or frontend settings;
- used historical architecture without current reconciliation;
- left component sources/licenses undecided;
- omitted schemas, state machines, owners, tests and Work Orders;
- called source-only or screenshot-only evidence implementation-ready.
- called a generic native dashboard responsive or structurally similar without
  proving visual density and interaction parity.

Fix the method, not only the current report. Prove semantic requirement
coverage.

## 2. Historical Reviewers and Branches

When the owner names a previous task:

1. Recover that exact task.
2. Read durable memory and only enough raw history to distinguish decisions
   from discussion.
3. Separate preserved product semantics from obsolete implementation.
4. Request reviews at the owner-named plan, pre-code and post-result gates.
5. Resolve findings and persist receipts.

Compare named branches by SHA, date, purpose, divergence, framework versions,
ownership and known failures. "Newest" is not a semantic decision.

## 3. Creative Suite, Image Agent, and Video Agent

Preserve these corrections:

- Creative Suite is a purchased/reference host experience.
- Image Agent is separate current-Core design, annotation, template-autofill,
  API/CLI/MCP and render-job capability.
- Video Agent is a separate timeline/media/rendering problem.
- Stable `field_key` semantics may remain, but raw Konva attributes or
  historical scene JSON are not automatically the target schema.
- Historical Konva is a candidate, not an accepted engine.
- Laravel 10, Blade, Alpine, Passport, PhotoStudio, loopback/shared secrets,
  fake HTTP drivers and private Node rendering remain historical evidence until
  current Laravel 13/React 19 owners accept them.
- Canvas engine, background renderer, AI provider and automation API are
  separate decisions. Canva Autofill, Placid, Shotstack or JSON2Video do not
  decide the editor engine.
- Marketplace prose or registrations do not prove AI Designer or Annotation
  source exists. Bind addon root/version/hash or mark `SOURCE_MISSING`.
- AI Designer and Annotation need independent packets, screenshots,
  proposal/editability contracts, errors and acceptance.
- Bind real CPU/RAM/queue/render topology before accepting "lightweight."

Enumerate every toolbar, panel, layer/timeline action, property, template
variable, asset operation, shortcut, responsive alternative, undo/redo,
save/conflict/recovery and export/render status.

## 4. Content Editors and AI Workspaces

Separate content list/open behavior, document editor, AI proposals, SEO side
panel, prompt/skill catalog, task lifecycle, dynamic publication channels,
revisions, sanitization, conflicts, exports and attachments.

Open content from the content item; keep task navigation as a separate explicit
action when required. Load channels, models, categories and prompts from their
native owner/settings, never hardcoded arrays.

## 5. CHAT and Channel Families

Keep inbox, widget, WhatsApp, Messenger, Instagram, Facebook, Telegram, Email,
Twitter/X and other approved channels separate until equality is proven.
Record controls, templates, attachments, provider states, errors,
retry/reconciliation and settings per channel.

For CHAT Inbox parity, freeze the real filter/search footprint, list-row
density, pane/header/composer measurements, scroll ownership, details
disclosure, desktop/mobile control placement and same-viewport screenshots.
Three panes plus mobile switching alone do not prove parity. Oversized filters,
buttons, cards or whitespace are material failures even when keyboard and
touch tests pass.

## 6. Core and App Settings

Inspect platform/admin settings, workspace/user frontend settings, app settings,
plan/credit/permission projection, and authorized runtime/provider config.

Cross-app reuse is valid only after current source proves the owner and
semantics. One app may own a stronger plan, channel, receipt, coupon, refund,
token-pack, notification or automation feature.

## 7. Quality Test

Reject the report if any answer is "the implementer can decide." Require the
owner ledger, version identities, UI/action/settings denominator, native owners,
schemas/states, security/performance/accessibility, screenshots or blockers,
bounded Work Orders, tests and reviewer receipts.
