# Methods and Tools

## Purpose

This consolidates the operational parts of the skills used for the canonical
CHAT library. The original skills are provenance, not runtime dependencies.

## Incorporated methods

| Source | Self-contained rule |
| --- | --- |
| Smooth Coding | Bind scope once, reuse before new, run decisive gates early, continue disjoint work, and review stable bytes once. |
| Ponytail | Use the first sound minimum solution; avoid speculative folders, abstractions, parsers, and repeated ceremony. |
| Devad Browser Proof | Define a proof matrix, protect privacy, verify narrow DOM facts first, and use honest PASS/PARTIAL/BLOCKED. |
| Devad Adoptions | Reference UI is evidence, not architecture; parity needs control, action, backend, permission, test, and browser contracts. |
| Devad Docs | Make artifacts usable without chat history and label evidence strength. |
| XPlan | Keep one canonical plan, route large references by signal, close full denominator segments, and validate paths/hashes/counts. |
| Devad X9 | Current Git/runtime wins; freeze identity, trace end to end, and separate source, deploy, and live proof. |
| Subagents | Default to none; one nonnested mechanical helper is allowed only when useful, and the parent verifies it. |
| Bundled Chrome | Use the real browser binding, read full browser documentation, reuse the binding, reacquire tabs, and never inspect session stores. |
| Chrome DevTools | Use only after same-profile attachment is proven; it is a read-only DOM/ARIA/console/network fallback, not an auth substitute. |

Do not use the POST chunk runner for CHAT packets. Do not substitute Page
Agent, standalone Playwright, Computer Use, or an isolated/in-app browser for
the required authenticated Chrome profile.

## Tool routing

1. Use `rg --files` for inventory and `rg -n` for exact searches.
2. Use Git objects for frozen native truth:
   - `git ls-remote <remote> <ref>`
   - `git grep <query> <sha> -- <scope>`
   - `git show <sha>:<path>`
3. Use PowerShell for hashes, bytes, line numbering, path/link checks,
   encoding/newline checks, and privacy scans.
4. Use bundled Python/Node for read-only HTML extraction and deterministic
   validation. Do not install dependencies when stdlib/bundled code works.
5. Use public web access for Board citation extraction.
6. Use bundled Chrome control for authenticated UI.
7. Use same-profile DevTools only for a required read-only fact.
8. Use `apply_patch` for authored Markdown and scripts.

## Gate order

Run cheap decisive checks before expensive collection:

- exact input path/hash/bytes;
- output collision and write authority;
- repository/ref/SHA;
- browser/profile route;
- parser/tool availability;
- denominator input counts;
- template/manifest shape.

Fix deterministic failures rather than asking a reviewer to reinterpret them.
After correction, rerun only the failed gate and affected downstream gates.

## Reuse-first admission

Before declaring a gap, record:

`EXISTING_FEATURE | UI_SETTINGS | SERVER_AUTHORITY | PLAN_ENTITLEMENT |
REFERENCE_REUSE | PERSISTENCE_CONSUMPTION | INTEGRATED_HISTORY | TEST_PROOF |
GAP | CHANGE_MODE`

Search current source, accepted predecessor commits, Sheet IDs, and owner-named
contracts. A Sheet/report is a lead, not proof. If another domain owns the
capability, integrate through that owner rather than cloning catalogs, provider
logic, queues, policies, or persistence.

## Optional helper

Use a helper only for a bounded mechanical task: counts, IDs, links, duplicate
checks, or secret-safe inventory. Bind exact paths, read-only scope, forbidden
browser/secrets/live actions, output schema, and stop bound. No nested helpers,
product decisions, broad context, or report authorship. Recheck decisive facts.
