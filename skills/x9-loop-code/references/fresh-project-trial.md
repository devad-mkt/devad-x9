# Fresh Project Controller Trial

## Purpose

Use this reference only after the owner has explicitly selected
`$x9-loop-code`. The Controller is a trial engine, not normal project
infrastructure and not a production workflow.

## Admission checklist

1. Confirm a fresh disposable repository/profile, current clean Git base, and
   no imported legacy Controller state.
2. Bind one canary outcome, claimed paths, focused proof, rollback, and one
   Looper owner in a durable packet.
3. Keep providers, deployment, credentials, recurring OS jobs, and destructive
   actions out of the trial unless separately owner-approved.
4. Install/initialize only after the packet and cheap preflight are green.

## Optional external one-hour check

The host—not Loop—may wake the designated Looper once per hour while a single
canary is active. A check is read-first: receipt, `doctor`, current ACTION,
and one dependency-ready local repair only. It emits a compact state change or
incident and otherwise stays quiet.

It must not create a scheduler, poll, issue provider/deploy calls, expose or
use credentials, alter task model/thinking, add roles, create a second work
order, retry a failed external effect, or patch Controller runtime state.
End it on PASS, FAIL, owner stop, or the first repeated deterministic failure.

## Exit

Record the exact source/installed hashes, proof, canary result, and rollback
status. Preserve failed evidence. Continue real project work through
`$x9-loop-style`, not through a recovery of this trial.
